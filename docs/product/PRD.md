# 自进化个人知识库 Agent 产品需求文档（PRD）

## 1. 文档信息

- 产品代号：Personal Knowledge Agent
- 文档状态：Deep Interview 已收敛，可进入架构规划
- 产品阶段：Greenfield / MVP
- 目标用户：单用户个人知识工作者
- 部署形态：服务器部署，可位于本地、自有服务器或云服务器
- 模型形态：本地模型与外部 API 均可配置
- 最终歧义：9%
- 需求来源：本次 Deep Interview、前序产品讨论、参考 PDF《深入理解 AI Agent：设计原理与工程实践》
- Context snapshot：`.omx/context/personal-knowledge-agent-memory-20260901T141414Z.md`

## 2. 产品定义

一个围绕个人完整生活建立的知识与决策系统：它按照稳定的领域体系管理知识，根据用户目标调用知识，通过长期反馈理解用户，并主动指出下一步值得补充的认知。

该产品不是简单的文件收藏夹、论文问答工具或静态用户画像，而是由个人知识、用户上下文、历史经历、决策记录和已验证 Agent 经验共同构成的长期个人认知助手。

## 3. 目标用户画像

公开版 PRD 使用泛化画像，不记录真实部署者的教育、职业、财务、关系或兴趣信息。

目标用户是一名需要同时管理专业资料、个人学习与日常生活知识的个人知识工作者。其知识范围可能包括：

- 专业研究、技术资料和长篇文档
- 职业发展与个人项目
- 公共信息与社会议题
- 金融素养与生活决策
- 创作、审美和生活方式
- 沟通、关系与个人成长
- 后续新增的兴趣与学习方向

用户能够理解结构化信息，但产品不要求其手工维护复杂的知识工程系统。真实用户画像和私人配置存放在部署环境中，不进入代码仓库。

## 4. 用户核心任务

### JTBD-1：保存和管理个人知识

当用户发现一篇论文、网页、新闻、图片或个人想法时，希望快速保存，由系统补全元数据、提取知识并归入稳定领域体系，同时保留原始证据。

### JTBD-2：查询和理解

当用户需要一个答案时，希望 Agent 同时使用用户当前目标、个人历史和知识库证据，给出可追溯、符合个人背景的回答。

### JTBD-3：辅助决策

当用户面对学习、职业、理财、消费、关系或生活选择时，希望 Agent 检索相关知识和历史决策，展示选项、约束、假设、风险和倾向性建议，但不代替用户执行外部动作。

### JTBD-4：发现知识缺口

当用户形成新目标或持续关注某个主题时，希望 Agent 识别知识库覆盖不足，解释为什么值得了解，并提供建议搜索方向；未经确认不得自动把外部材料写入知识库。

### JTBD-5：持续变得更懂用户

当用户长期使用系统时，希望看到画像如何变化、变化依据是什么，并决定是否让推断生效。

## 5. 产品目标

1. 让用户能够长期保存、定位和调用跨领域个人知识。
2. 让回答和建议同时具备个性化与证据可追溯性。
3. 让知识库结构稳定，但允许知识状态、关系和摘要持续更新。
4. 让 Agent 通过经过验证的反馈持续改善检索、推荐和服务策略。
5. 让所有重要记忆更新可解释、可确认、可撤销。

## 6. 非目标

首版明确不包含：

- 多用户、多租户、组织权限和公共知识空间
- 商业 SaaS 计费、团队协作和公共社区
- 个人模型微调、在线训练或自动修改模型参数
- 自动交易、发信、发消息、下单、发布内容等对外执行
- 未经用户确认自动采集并正式入库外部知识
- 未经用户确认使 Agent 推断的敏感画像生效
- 一开始建设复杂的通用知识图谱或专用图数据库
- 为未来不确定需求提前搭建分布式微服务体系

## 7. 产品原则

1. 原始证据永远不被摘要替代。
2. 用户事实、Agent 推断和外部知识必须明确区分。
3. 用户画像可以影响建议，但不能扭曲事实。
4. 一次行为不能自动形成长期偏好。
5. 推断可以自动产生，生效必须由用户确认。
6. 目录负责浏览，检索和关系负责连接。
7. 向量索引只是派生数据，不是事实来源。
8. 简单问题使用简单检索，复杂问题才使用 Agentic RAG。
9. 在线服务只记录证据和候选更新；正式进化在离线验证后发生。
10. 所有正式记忆和能力修改必须可追溯、可撤销、可回滚。

## 8. 知识分类体系

一级分类采用稳定的 MECE 生活领域：

1. 学术与职业
2. 技术与工程
3. 金融与资产
4. 社会与公共议题
5. 学习与个人发展
6. 健康与身心
7. 关系与沟通
8. 生活方式与审美
9. 艺术与创作
10. 个人档案与经验

规则：

- 每条知识只有一个主分类，回答“它主要帮助解决哪个领域的问题”。
- 可以拥有多个标签、实体和跨领域关系。
- 掌握程度是认知属性，不参与一级分类。
- 目录结构可版本化调整，但不得自动大规模重组正式知识库。
- 跨领域内容不得复制多份，应通过唯一 ID 和关系链接复用。

## 9. 记忆模型

记忆采用四个正交维度，而不是简单的并列文件夹。

### 9.1 归属

- 用户记忆：关于用户本人、目标、偏好和约束
- 领域知识：关于外部世界的专业和生活知识
- Agent 经验：关于在什么条件下怎样服务用户

### 9.2 生命周期

- 原始轨迹：只增不改的对话、工具结果和反馈
- 工作记忆：当前任务筛选后的动态上下文
- 长期记忆：跨会话保存的正式记忆
- 当前状态：目标、项目、计划和决策的结构化有效状态

### 9.3 认知类型

- 语义记忆：用户稳定画像、概念、事实和一般知识
- 情景记忆：经历、项目事件和决策过程
- 程序记忆：已验证的工作方法、经验和 Skill

### 9.4 表示形式

- 原子事实
- 结构化卡片
- Markdown 叙事文档
- 可执行状态和确定性规则

## 10. 存储架构要求

### 10.1 原始证据层

以原始文件、网页快照、图片和只增事件日志保存：

- PDF、网页、图片、音频、视频
- 原始对话和工具结果
- 用户反馈
- 决策实际结果

所有整理后内容必须保留证据引用。

### 10.2 正式记忆层

结构化、高频更新的数据进入关系型数据库：

- 用户身份、角色、兴趣、偏好和约束
- 目标、项目和当前状态
- 记忆条目、实体和关系
- 版本、生效时间、失效时间和置信度
- 决策状态、反馈和推荐记录

长篇、人类可阅读的内容使用 Markdown：

- 知识笔记
- 决策记录
- Agent 经验文档
- Skill 和流程说明

每类数据只能有一个权威来源，避免数据库与文件双向编辑冲突。

### 10.3 检索索引层

- 全文/BM25 索引用于标题、作者、术语、日期和原文精确匹配。
- 向量索引用于语义召回、相似观点和跨领域联系。
- 时间、实体、状态、来源质量和敏感等级作为过滤条件。
- 索引必须能从正式记忆和原始证据重建。
- MVP 不强制使用独立向量数据库或图数据库。

### 10.4 MVP 技术基线

- 文件系统或对象存储：原始资料和 Markdown 内容
- SQLite：单用户结构化数据、版本和关系
- SQLite FTS5：全文检索
- 本地向量索引或 SQLite 向量扩展：语义检索
- 模型适配层：支持本地模型与外部 API
- 后续仅在并发、规模或远程同步出现明确瓶颈时迁移到 PostgreSQL 或独立向量服务

## 11. RAG 设计

### 11.1 不使用 RAG 的场景

- 当前身份、目标和项目状态
- 明确偏好和约束
- 精确日期、预算和枚举状态
- 当前任务工作记忆

这些信息通过结构化查询直接读取。

### 11.2 普通混合 RAG

适用于论文、知识笔记、历史经历和一般知识查询：

1. 查询理解和必要的查询改写
2. BM25 与向量并行召回
3. 实体、时间、状态、权限和来源过滤
4. 候选融合与重排序
5. 加载原始证据
6. 生成带证据引用的答案

### 11.3 Agentic RAG

仅用于复杂综合和决策问题。Agent 可以拆分子问题、多轮检索、检查信息充分性、处理冲突并回到原始资料核验。简单事实查询不得默认使用多轮 Agentic RAG。

### 11.4 双层用户记忆

- L0 核心画像：身份、人生阶段、高优先级目标、活跃项目、关键约束和风险，体积严格受限并在任务开始时加载。
- L1 主题概览：按当前领域或项目加载摘要。
- L2 原始细节：通过 RAG 检索原始对话、决策记录和证据。

Agent 可以用 L0 发现潜在联系，但在给出重要判断前必须用 L2 核验。

## 12. 核心功能需求

### FR-01 知识导入

- 支持 PDF、网页、Markdown、图片和手工笔记。
- 保留原文件、来源、作者、时间和导入时间。
- 自动提取正文、章节、知识单元和候选关系。
- 自动建议主分类和标签，用户可修改。
- 外部搜索内容必须经过用户确认才能正式入库。

### FR-02 用户画像

- 管理身份、角色、人生阶段、目标、项目、兴趣、偏好和约束。
- 每条画像包含来源、证据、时间、置信度和状态。
- 用户明确事实与 Agent 推断使用不同状态和视觉标识。
- 推断型画像必须经用户确认后生效。

### FR-03 记忆中心

- 查看正式记忆、候选记忆和历史版本。
- 支持确认、拒绝、修改、删除和恢复。
- 展示记忆为何生成、引用了哪些证据、影响哪些推荐。

### FR-04 知识问答

- 自动判断结构化查询、普通 RAG 或 Agentic RAG。
- 回答必须区分知识库证据、用户画像、模型推理和未验证假设。
- 重要事实提供来源和原文定位。
- 信息不足或存在冲突时明确说明，不强行生成确定结论。

### FR-05 决策支持

- 明确决策问题、目标、约束和候选方案。
- 检索相关知识、用户状态和历史决策。
- 展示收益、成本、风险、机会成本和关键假设。
- 提供倾向性建议与改变结论的条件。
- 保存决策过程，并允许后续复盘实际结果。
- 不执行交易、发送或其他外部动作。

### FR-06 知识缺口推荐

- 区分“知识库缺少资料”和“用户尚未掌握”。
- 基于目标依赖、知识覆盖、资料质量、时效和观点多样性提出推荐。
- 每条推荐解释原因、相关目标、建议搜索词、来源类型、优先级和学习成本。
- 不得把知识库缺失直接表述为用户能力不足。

### FR-07 自进化中心

- 展示画像变化、检索策略变化、推荐变化和 Agent 经验变化。
- 每次变化显示依据、适用范围、验证结果和回滚入口。
- 用户可以暂停某类推断或推荐。

### FR-08 多模态知识

- 摄影、穿搭和论文图表必须保留原图。
- 文本描述只用于辅助检索，不得替代视觉证据。
- 首版至少支持图片元数据、描述和原图回看；多模态向量检索可以作为增强能力。

## 13. 记忆写入规则

| 输入 | 默认处理 |
|---|---|
| 用户明确表达且无歧义的事实 | 写入确定性候选，可快速确认或按配置自动生效 |
| 用户明确表达的新目标 | 写入目标候选，展示将影响的推荐 |
| Agent 从一次行为推断的偏好 | 仅进入候选区 |
| Agent 从多次行为推断的稳定偏好 | 进入高置信候选区，仍需确认 |
| 敏感画像推断 | 必须确认后生效 |
| 外部知识 | 保存为证据候选，确认后正式入库 |
| Agent 服务经验 | 经跨轨迹验证后才可发布 |
| 当前任务临时信息 | 只进入工作记忆，任务后自动过期 |

## 14. 自进化闭环

### 在线执行循环

1. 稳定版本处理真实任务。
2. 记录只增不改的轨迹、工具结果和反馈。
3. 生成候选画像、候选知识或候选经验。
4. 在线循环不得直接修改正式 Agent 策略和安全门槛。

### 离线进化循环

1. 聚合同类成功、失败和部分成功任务。
2. 分别评价结果、过程和质量。
3. 提取共同模式、适用条件和反例。
4. 生成最小、可审查、可回滚的更新提案。
5. 在迁移集、保留集和安全集上验证。
6. 通过后灰度应用；异常时自动或人工回滚。

### 不可自修改可信根

以下内容不能由普通进化流程修改：

- 用户确认门槛
- 权限和隐私规则
- 审计日志
- 评测集和发布阈值
- 稳定版本备份
- 外部动作禁令

### 持续进化实施规范

持续进化采用以下已确认方案：

- 三层证据型学习信号：分别评价结果、过程和质量。
- Agent 提议更新位置，确定性规则负责路由门禁。
- 提案使用 `candidate → evidence_ready → validating → approved → canary → stable → archived` 状态机，并支持拒绝、回滚和废止。
- Proposer 与 Reviewer 权限分离，高风险变化需用户确认。
- 使用固定基准＋动态案例组成边界集、迁移集、保留集和安全集。
- 发布采用风险分级策略，安全新增失败立即回滚。
- 睡眠学习由周期和事件共同触发，并包含冲突处理、修剪、归档和索引重建。
- MVP 首个完整行为进化闭环为检索与回答策略进化。

具体字段、权限、状态转移和验收规则见 [持续进化架构规范](../architecture/continuous-evolution.md)。

## 15. 主要用户流程

### 流程 A：导入论文

上传 PDF → 保存原文件 → 提取元数据与章节 → 生成知识单元和分类建议 → 用户确认 → 建立全文与向量索引 → 可问答和引用。

### 流程 B：形成用户画像

用户对话 → 提取明确事实与推断 → 明确事实按配置处理 → 推断进入候选中心 → 用户确认/修改/拒绝 → 更新正式画像和 L0 摘要。

### 流程 C：复杂决策

识别决策问题 → 加载当前目标和约束 → 多轮检索知识与历史决策 → 标记信息缺口和假设 → 生成方案比较与建议 → 用户决定 → 保存决策 → 到期提醒复盘。

### 流程 D：知识缺口推荐

读取活跃目标 → 获取目标所需知识 → 计算知识库覆盖和质量 → 生成解释性推荐 → 用户手工搜索或忽略 → 经确认后导入新知识。

## 16. 权限和隐私

- 产品为单用户系统，但仍要求认证和会话保护。
- 支持本地模型和外部模型 API；外部发送由部署者在私人配置中显式启用，并可按敏感等级选择模型路由。
- 必须展示当前使用的模型供应商并保存必要调用审计。
- API 密钥不得写入知识库、日志和模型上下文。
- 所有传输必须加密。
- 用户可以删除资料、记忆、向量索引和对应派生摘要。
- 外部文档、网页和模型输出均作为不可信数据处理，不得作为系统指令执行。

## 17. 成功指标与验收标准

### 17.1 功能验收

- 可以完成 PDF/网页/Markdown/图片导入并保留原始证据。
- 所有正式知识和用户记忆都可追溯到来源。
- 所有推断型画像在用户确认前不影响正式推荐。
- 用户可以查看、修改、删除和回滚正式记忆。
- 复杂回答能展示证据、假设和冲突。
- 决策建议不触发任何外部执行动作。
- 未经确认的外部知识不会进入正式知识库。

### 17.2 记忆评测

- 基础回忆：结构化确定事实准确率目标不低于 95%。
- 多会话检索：标注测试集 Top-10 证据命中率目标不低于 90%。
- 主动服务：推荐必须关联至少一个用户目标或明确知识结构缺口。
- 推断误生效：未确认推断进入正式画像的数量必须为 0。
- 删除和回滚：测试样例成功率必须为 100%。

### 17.3 RAG 评测

- 建立包含论文标题、精确术语、跨文档综合、时间冲突和反方观点的评测集。
- 同时跟踪 recall@k、首条相关结果排名、引用覆盖率和过时内容误召回率。
- 混合检索不得低于仅向量检索在保留集上的整体表现。
- 重要事实性回答必须能够定位到正式知识或原始证据。

### 17.4 进化评测

- 更新提案有效率
- 新记忆或 Skill 的正确激活率
- 激活后的遵循成功率
- 未参与提炼任务上的迁移增益
- 原有任务保留率
- 安全、隐私、延迟和 Token 成本变化

## 19. 风险与应对

| 风险 | 应对 |
|---|---|
| 用户画像错误固化 | 推断确认门、证据与置信度、版本回滚 |
| RAG 漏召回 | 混合检索、重排序、时间与实体过滤、评测集 |
| 摘要漂移 | 回到原始证据定期重建 |
| 知识越来越杂乱 | 增量更新＋定期整理＋MECE 入口和关系索引 |
| 推荐形成信息茧房 | 目标相关、基础补全、反方观点和跨领域探索共同排序 |
| 外部资料提示注入 | 指令与数据隔离，外部内容不得触发高风险行为 |
| 自进化造成能力回退 | 待验证区、迁移集、保留集、安全集、灰度与回滚 |
| 文件和数据库不一致 | 每类数据指定唯一权威来源，索引只读派生 |

## 20. Decision Boundaries

后续架构和实现团队可自行决定：

- SQLite 具体表结构和索引结构
- 嵌入模型、重排序模型和外部模型供应商适配方式
- Markdown 模板、ID 规范和目录命名
- 后台任务调度方式
- 不改变产品边界的 UI 信息架构细节

必须再次获得用户决定：

- 新增任何对外自动执行能力
- 放宽推断型画像确认门槛
- 自动抓取并正式入库外部知识
- 引入多用户或共享知识空间
- 开始个人模型训练或微调
- 改变敏感数据删除和审计边界

## 21. Assumptions

- 本地模型和外部模型 API 的使用范围由部署者在仓库之外的私人配置中决定。
- 单用户规模下，SQLite 与本地检索索引足以支撑 MVP。
- 用户愿意确认重要画像变化，但系统应尽量批量、低打扰地呈现候选项。
- 知识库主要服务个人长期使用，而非公开发布或多人协作。
- 知识建议可以自动生成，但正式入库由用户确认。
