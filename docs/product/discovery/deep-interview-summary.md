## 访谈结论

### 产品产物

输出一份完整产品 PRD，可直接作为后续架构规划和 MVP 拆解的需求来源。

### 产品边界

- 只服务用户本人的单用户产品。
- 不为未来多用户或商业 SaaS 预先设计复杂租户能力。
- 部署在服务器上，服务器可以是本地设备、自有服务器或云服务器。
- 模型层可使用本地模型，也可调用外部模型 API。
- 外部模型的具体数据范围由部署者在仓库之外的私人配置中决定。

### 记忆自治边界

- 用户明确表达的事实可按照规则形成候选或确定性记忆。
- Agent 根据行为、对话或资料推断出的画像变化，必须进入候选记忆区。
- 推断内容只有在用户确认后，才能进入正式画像并影响后续推荐和决策建议。
- 所有正式记忆必须可查看、修改、删除、追溯和回滚。

### 首版范围

- 知识采集与管理
- 用户画像
- 基于个人知识库的问答
- 决策建议
- 候选记忆确认
- 知识缺口识别与推荐
- 可解释的自进化记录

### 首版非目标

- 多用户和多租户能力
- 个人模型训练、持续微调或自动修改模型参数
- 自动交易、发信、发消息、下单等对外执行动作
- 未经用户确认自动将外部搜索结果写入正式知识库
- 未经用户确认使推断型用户画像生效

## 压力测试发现

“只服务个人”并不等于“完全本地运行”。产品支持服务器或云服务器部署，但必须保留模型供应商可替换、传输保护、调用记录、删除和数据导出能力。敏感内容的模型路由属于私人部署配置。

另一个关键假设是“Agent 越了解用户越好”。经压力测试后确定：理解可以自动产生，生效不能自动发生。推断型画像必须由用户确认，避免一次对话将敏感推断固化为长期事实。

## 逐轮记录

1. 期望产物：完整产品 PRD。
2. 产品用户：只服务用户个人的单用户产品。
3. 部署与模型：部署在服务器上；模型可本地运行或通过 API 调用。
4. 模型路由：支持本地与外部模型，具体数据范围由私人配置决定。
5. 推断型画像：等待用户确认后生效。
6. 首版范围收口：确认首版仅覆盖知识、画像、问答、建议、候选确认和知识缺口推荐；不做多用户、个人模型训练、自动对外行动和未经确认的外部知识自动入库。
