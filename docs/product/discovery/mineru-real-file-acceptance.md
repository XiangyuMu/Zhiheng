## 第一轮已接受决策（2026-10-09）

1. 部署成果：留下可重复启动、停止和诊断的本地部署入口，以及持久模型缓存，而非仅本次会话临时进程。
2. 验收范围：独立验收解析/索引/检索及原文定位；把 DeepSeek 基于该 PDF 生成正确且可核对的回答列为另一必过门禁，不绕过发布或授权规则。
3. 恢复能力：将解析中 Worker/网关重启纳入验收，要求有界恢复或明确失败并可重试，不丢原文、不发布重复正式版本或不完整结果。

## 新核实的实现缺口

- Worker 的生产配置仍以 DeepDoc 为启用前提；单独配置 MinerU 当前不会启用 PDF 执行器。
- DeepDoc 转 MinerU 的 fallback 构造请求时未传递 evidence_object_id；正常主路径已传递不等于 fallback 已修复。
- gateway 的任务映射仅存在内存中，尚不满足已接受的重启恢复验收。
- Compose 尚无 gateway 服务，实际部署接线仍需补齐。
- 容器退出码 137 本身不能证明 OOM；此前有主动停止模型下载的记录，必须核实 OOMKilled 和事件，不能据此断言资源不足。

4. 本地部署允许显式选择 MinerU 为主解析器，保留 DeepDoc 的独立选项；任务及 manifest 按实际引擎记录，不将 MinerU 伪装为 DeepDoc。

## 实施顺序与验收证据

1. 补齐真实协议：主解析器选择、fallback 身份传递、manifest/图片引用完整性；通过生产客户端到网关的契约测试。不得以模拟响应替代真实解析成功证据。
2. 部署入口：启动、停止、健康检查和诊断覆盖网关及 MinerU，记录镜像版本、模型缓存、资源和配置摘要；不保存密钥。网关存活、上游存活、模型就绪分别记录。
3. 恢复：持久关联本地尝试与上游任务，覆盖 Worker 和网关重启、上游任务丢失、提交响应不确定、旧 lease 回写；不确定提交不得无条件重发。原文保留，失败可重试，正式发布幂等。
4. 真实浏览器上传 Comments.pdf；记录输入 SHA256、任务/尝试/证据对象标识、实际解析引擎、manifest URI 与摘要、页数和引用位置，验证索引指针及原文均存在。
5. 验证搜索命中本次导入对象，点击引用回到该 PDF 对应页/原文；不能使用历史同名对象冒充本次结果。预先从原文件选定可核对的问题与预期依据。
6. 独立验证 DeepSeek 回答内容、引用来源及调用审计；加入一个材料未提供答案的问题，检验是否如实表示证据不足。不通过修改发布或授权门禁强行生成回答。
7. 强化脚本：每次等待本次请求和页面更新；按当前任务轮询，失败、部分结果和超时非零退出；无论成功失败均保存报告。截图和报告留在受限持久目录，个人材料不提交仓库。
8. 最终候选在干净检出完成迁移、API/Worker 启动、Ruff、Mypy、全量 pytest 和真实浏览器验收。保存 SHA、命令、版本、退出码、耗时、完整日志及需求映射；全量 pytest 的 900 秒预算另行判定，不复用旧 SHA 证据。

## 完成判据

解析/索引/检索及原文定位、DeepSeek 引用回答、中断恢复三组均须通过，并有最终候选的质量门禁证据。仅有网关代码、健康检查、模型探测或绿色单元测试不构成完成。外部服务失败时保留诊断与明确失败结果，不更换为模拟服务或静默更换模型。
