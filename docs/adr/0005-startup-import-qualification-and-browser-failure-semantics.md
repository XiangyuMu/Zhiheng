# 启动屏障、导入资格与浏览器失败语义

本轮修复采用四个相互关联的边界：Provider 配置沿用现有数据库结构并补齐服务层；API 与 Worker 在使用数据库前共同通过迁移和恢复启动屏障；只有原文对象与索引指针都存在且任务状态为 `succeeded` 的导入内容才具备正式检索资格；浏览器对不支持、失败和暂时不可确认的状态分别处理，不把轮询超时解释为成功。

**Status:** accepted

## Decisions

- Provider 只保存外部密钥引用，接口不回显明文密钥或引用值。
- 迁移或恢复屏障失败时，API 和 Worker 都拒绝启动。
- 缺少可选解析能力的任务进入 `unsupported` 终态，记录稳定错误码和用户可读原因；Worker 继续处理其他任务。
- `queued`、`processing`、`failed`、`unsupported` 和 `partial` 状态都不能进入正式回答上下文。
- 浏览器收到状态接口 `404` 时停止轮询并提示当前服务版本不支持；`5xx` 或网络错误只进行有限次退避重试。
- 真实浏览器验收必须同时启动真实 API 和 Worker，并覆盖成功、失败和不支持场景。

## Consequences

- 导入状态、对象存储和检索索引必须能被一致地验证，不能只依赖单个任务记录。
- 启动问题会更早暴露，API 或 Worker 不能通过降级启动掩盖 schema 不一致。
- 可选能力的缺失变成可观察的业务终态，而不是无限轮询或错误成功。
- 交付门禁需要保存成功链路和失败链路的浏览器证据。
