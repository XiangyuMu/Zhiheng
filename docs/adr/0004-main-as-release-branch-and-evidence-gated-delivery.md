# 以 main 为唯一交付分支并采用证据门禁

项目将 `main` 作为唯一最终交付分支。其他分支上的 #1–#18 产品修改按票据或功能组分批合并到 `main`，每批合并前都必须通过对应测试和代码审查；未提交修改先按产品文件、必要文档和临时状态分类，不能直接作为交付内容。第一版只有在干净检出中通过编译、规范检查、类型检查、数据库迁移、API/Worker 启动和真实浏览器验收，并保存提交 SHA、命令、日志、截图及需求映射后才能交付；Issue 只能凭合并到 `main` 和对应验收证据关闭。这样可以保留每批变更的可回退边界，避免把本地工作树或历史绿色测试误当成最终版本。

**Status:** accepted

## Consequences

- `main` 的每个交付提交都必须可从干净检出重复验证。
- OMX 状态、缓存、临时实验和无法追溯来源的文件不属于产品交付。
- 尚未通过门禁的功能可以继续存在于工作分支，但不能宣称已完成或关闭票据。
- 交付审查需要同时检查提交范围、工作树状态、规格覆盖和新鲜动态证据。
