# 对话结论的审核与适用性边界

用户希望优先让知识更加成熟，其次增进对用户的理解，最后改善回答能力。为支持集中审核而避免未经认可的推断影响后续回答，对话提炼内容允许保存为待审核草稿，但须经用户同意才能成为正式知识；待审核内容不能用于后续回答。

结论必须同时记录成立前提。前提发生变化时，系统可以自动暂停使用旧结论作为当前建议的依据，将其标为当前适用性待复核，并保留原结论及历史前提；修订内容仍须用户同意。暂停使用不等于推翻原结论，用户批准也不等于客观证实。

未确认的前提保留为假设；即使结论已经获准入库，也只能在“如果此前提成立”的条件下使用，不能把假设视为用户的实际情况。该规则不赋予待审核草稿用于后续回答的资格。

自动暂停以明确事实变化或已知有效期届满为依据。含糊表达和系统推测只触发复核提醒，不自动暂停。

知识归属沿用[现有分类规范](../product/domain-taxonomy.md)的唯一主领域与跨领域关联，避免跨领域知识的重复存储。

该决定明确了用户审核权与系统暂停使用权的分工。它接受审核积压可能延迟新知识生效的代价，以保留用户对正式知识的控制。

用户明确且无冲突的个人陈述可自动进入长期记忆，保留来源和时间；引用、假设和玩笑不视为明确陈述。用户明确表达有时间变化的个人情况时，可自动更新当前信息并保留历史。系统推断出的画像仍须用户确认；个人信息的自动记忆规则不放宽对话提炼结论的审核要求。

个人信息发生冲突时，系统须主动弹窗请用户选择或澄清，允许稍后处理并保留待办；无关问题正常回答。当前问题依赖尚未解决的冲突信息时，先回答不依赖冲突的部分；依赖部分能分情况说明时明确列出条件，无法给出可靠的条件式回答时暂缓该部分并说明需要确认什么。用户延后处理不构成对任何一条冲突信息的确认，系统不擅自选择冲突记录。

只有缺失信息会实质影响当前回答、结论前提或正在进行的任务时，才主动弹窗收集，并说明询问原因、允许跳过。

对话形成实质性判断时，系统自动生成待审核草稿，并随讨论补充前提与依据。用户可随时打开待审核列表集中处理；普通草稿只显示待审核数量，仅在用户明确要求保存或主动打开审核时展示确认界面。请求保存触发展示审核内容，不替代对具体内容的同意。

完整原始对话可供回看、审核和追溯。跨对话回答使用对话衍生内容时，只能使用已批准的结论或符合自动记忆规则的个人信息；未经审核的判断不能通过检索原始对话间接进入回答。该约束针对原始对话，不替代外部资料的使用规则。

审核新结论时，展示与已有知识的关系：重复内容建议合并并补充来源；补充或修正展示差异，经用户同意形成新版本并保留历史；前提不同的结论可并存，须明确各自适用条件；相同前提下真正冲突的结论标记争议并请用户判断，不因产生时间较晚就覆盖旧结论。

个人信息保留最后确认时间。对于没有明确有效期的目标、计划和临时状态等易变信息，在相关任务再次使用时主动确认；稳定信息不频繁询问，单纯经过一段时间不自动改写事实。此处的时效复核不同于已知有效期届满触发的自动暂停。
