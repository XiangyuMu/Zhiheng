# 持续进化架构规范

## 1. 文档目的

本文规定知衡如何从运行经验中产生、验证、发布和淘汰持久更新。持续进化不是保存反馈或不断追加记忆，而是完成：

```text
评价 → 对照 → 归纳 → 验证 → 灰度 → 发布或回滚
```

本规范适用于用户记忆、经验文档、检索策略、Prompt/Skill 和程序规则。MVP 不更新模型参数。

## 2. 已确认决策

| 决策项 | 选择 |
|---|---|
| 学习信号 | 三层证据型 |
| 更新对象路由 | Agent 提议＋规则门禁 |
| 提案状态机 | 七状态标准版 |
| 独立审核 | Reviewer Agent＋风险分级用户确认 |
| 评测集 | 固定基准＋动态案例 |
| 发布方式 | 风险分级发布 |
| 睡眠学习 | 周期＋事件混合触发 |
| MVP 首个行为进化闭环 | 检索与回答策略进化 |

## 3. 学习信号 Schema

每次可用于学习的任务评价必须包含：

```yaml
evaluation_id: string
task_id: string
task_family: string
agent_version: string
knowledge_version: string
environment_version: string
result:
  status: success | partial | failure
  evidence_refs: []
process:
  violations: []
  evidence_refs: []
quality:
  rubric_scores: {}
  evidence_refs: []
failure_tags: []
confidence: number
user_feedback: optional
learning_eligible: boolean
created_at: datetime
```

信号可信度顺序：

```text
确定性结果
> 数据库或工具状态
> 规则检查
> 带证据的 LLM Rubric
> 用户满意度
```

约束：

- 证据不足时允许拒绝评分。
- 低置信度案例不得自动进入学习集。
- 用户点赞、接受或忽略只能作为辅助信号。
- 结果正确不代表过程正确，三层评价必须分别保留。

## 4. 更新对象路由

Agent 可以提出修改位置，但必须通过确定性门禁：

| 内容 | 允许的主要载体 |
|---|---|
| 用户明确事实、偏好和目标 | 用户记忆 |
| 外部事实、概念和来源 | 知识库 |
| 跨轨迹总结出的行动经验 | 经验文档 |
| 可语言化的判断原则 | Prompt 或领域 Skill |
| 确定流程、高风险约束 | 程序或 Harness |
| 高维风格和隐式能力 | 模型参数，MVP 禁止 |

固定门禁：

- 事实不得写入系统 Prompt 充当永久规则。
- 用户偏好不得升级为所有场景生效的全局规则。
- 安全、权限和确认边界不得只由可检索文档保证。
- 硬约束必须由程序或 Harness 执行。
- 普通进化流程不得修改可信根。

## 5. 提案状态机

正常路径：

```text
candidate
→ evidence_ready
→ validating
→ approved
→ canary
→ stable
→ archived
```

异常状态：

```text
rejected
rolled_back
deprecated
```

每个提案至少包含：

- 提案 ID 和目标组件
- 来源轨迹和任务族
- 支持证据和反驳证据
- 适用条件、环境版本和例外
- 修改前版本和最小 diff
- 风险等级
- 验证报告
- Proposer 与 Reviewer 身份
- 发布时间、稳定版本和回滚目标

只有 `stable` 状态能够无条件服务正式请求。`canary` 只能在受控范围内生效；其他候选状态不能影响正式行为。

## 6. 独立审核与权限

角色：

- Proposer Agent：分析已评价轨迹并提出最小修改。
- Reviewer Agent：独立读取原始证据、现有版本、diff 和评测结果。
- 用户：批准高风险修改和所有推断型画像。

审批规则：

| 风险 | 示例 | 审批要求 |
|---|---|---|
| 低 | 标签、链接、非关键摘要 | Reviewer 可批准 |
| 中 | 检索权重、推荐排序、回答 Skill | Reviewer 批准后进入 canary |
| 高 | 用户画像、金融/健康/感情策略、Prompt、程序规则 | Reviewer＋用户批准 |
| 可信根 | 权限、审计、验证器、发布门槛、稳定备份 | 禁止普通进化流程修改 |

Reviewer 不能只阅读 Proposer 挑选的摘要，必须拥有其权限范围内的原始证据读取能力。生成者不能批准自己的提案。

## 7. 评测集

### 7.1 固定核心集

- 迁移集：与经验相关但未参与提炼的新任务。
- 保留集：旧版本已经稳定通过的任务。
- 安全集：隐私、提示注入、越权、错误事实、确认门和外部动作禁令。
- 边界集：直接触发本次修改的失败和相邻边界场景。

### 7.2 动态案例集

从近期真实轨迹、失败、用户纠正和新型攻击中生成候选案例。自动生成案例必须审核后才能加入正式评测集。

### 7.3 发布前提

- 边界集必须改善。
- 迁移集必须证明正向迁移或至少不劣。
- 保留集不得超过批准的回退阈值。
- 安全集不得产生新增违规。
- 成本和延迟不得超过版本预算。

具体数值阈值必须在实现前由架构与测试规范确定，普通进化流程无权修改。

## 8. 风险分级发布与回滚

### 低风险

```text
自动验证 → canary → stable 或 rolled_back
```

### 中风险

```text
Reviewer 批准 → canary → 指标达标 → stable
```

### 高风险

```text
独立审核 → 用户批准 → canary → stable
```

立即回滚条件：

- 安全集出现新增失败。
- 未确认推断影响正式行为。
- 原有能力超过阈值回退。
- 用户明确否定或停用。
- 来源证据被推翻且继续使用会造成风险。

暂停并审核条件：

- 成本或延迟超过预算。
- 指标异常但证据不足。
- 新旧经验冲突且适用条件无法消歧。

## 9. 睡眠学习与淘汰

采用周期＋事件混合触发。

事件触发：

- 同类错误累计达到约定阈值。
- 发生安全问题。
- 经验或知识出现冲突。
- 检索失败率超过阈值。
- 用户主动要求整理。

周期触发：

- 每周：整理新经验、重复项和冲突。
- 每月：全量检查陈旧内容、索引质量和容量。
- 每季度：重新验证长期未使用的 Skill 和经验。

淘汰规则：

- 被新证据推翻：`deprecated`。
- 只适用于旧环境：增加环境限定，必要时停止默认检索。
- 长期未使用：重新验证后保留或归档。
- 重复经验：合并，保留全部来源。
- 持续验证失败：`archived`。
- 失败、拒绝和停止原因必须保留，避免幸存者偏差。

修剪后必须重建受影响的全文、向量和摘要索引，同时保留原始证据与回滚版本。

## 10. MVP 行为进化闭环

首个闭环聚焦检索与回答策略：

- 结构化查询、普通 RAG 和 Agentic RAG 的路由。
- BM25 与向量召回组合。
- 是否需要二次检索和原文核验。
- 引用数量和证据覆盖。

闭环流程：

```text
回答任务
→ 结果/过程/质量评价
→ 聚合同类成功、失败和部分成功轨迹
→ 生成检索策略最小修改
→ 边界/迁移/保留/安全验证
→ Reviewer 审核
→ canary
→ stable 或 rolled_back
```

核心指标：

- 证据命中率
- 回答正确性
- 引用覆盖率
- 冲突和时效遗漏率
- 路由正确率
- Token、延迟和模型调用成本
- 原有任务保留率

## 11. MVP 完成定义

只有同时满足以下条件，才能宣称 MVP 实现了持续进化：

1. 存在真实的已评价任务轨迹。
2. 能从多条轨迹形成带支持与反驳证据的提案。
3. 提案经过独立 Reviewer。
4. 提案通过边界、迁移、保留和安全验证。
5. 提案能在 canary 中改变检索或回答行为。
6. 系统能根据效果晋升稳定版或自动回滚。
7. 所有版本、证据和决策均可审计。
